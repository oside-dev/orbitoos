# Learning next content moves playbook

**Scope:** the existing OrbitOS analytics and learning loop. This is advisory only. It does not change publishing flags, schedules, or worker behavior.

## Purpose

OrbitOS already captures metrics, learning insights, and content strategy. This playbook tells an operator how to turn that data into the next approved idea.

## Decision rules

1. **Pick the platform with the strongest engagement rate.**
   - Prefer the platform that combines a strong rate with meaningful reach.
   - Use it as the first candidate for the next high-priority variant.

2. **Repeat the strongest content angle, not the exact post.**
   - Reuse the highest-performing hook, audience promise, or proof pattern.
   - Reframe it for the platform instead of copy-pasting the old caption.

3. **Use learning insights as constraints, not commands.**
   - If learning says a topic is weak, narrow the audience or change the angle.
   - If learning says a hook is strong, preserve the opening beat and adjust the body.

4. **Choose the next format by friction.**
   - If one platform is clearly outperforming the others, make the next draft native to that format first.
   - Create variants for the remaining platforms after the best-performing one is approved.

5. **Keep the human approval gate.**
   - OrbitOS may suggest the next move, but the operator still decides what gets approved.
   - This is a planning aid, not a publishing control.

## Recommended operator flow

1. Open **Analytics** and run the learning loop after new metrics arrive.
2. Review the latest learning insights and the top-performing platform.
3. Draft a new idea that reuses the best angle.
4. Generate platform variants.
5. Approve the revised draft before scheduling.

## Safety reminder

Do not use this playbook to infer live publishing success. A CI pass, a learning insight, or a high engagement rate is not the same as a verified post in the connected social account.
